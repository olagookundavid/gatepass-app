# reports (`lambda-nightly-report`)

## Purpose

A daily AWS Lambda that writes **yesterday's sales per event** as a CSV file to S3: `reports/YYYY/MM/DD.csv` (UTC days).

```
EventBridge Scheduler (daily) -> Lambda (in the VPC)
   -> RDS PostgreSQL  as the read-only user orders_report, IAM database authentication
   -> S3 PutObject    reports/2026/02/28.csv   (overwrites)
```

## Columns

`date,event_id,currency,orders_paid,tickets,gross_cents,orders_still_paid`: orders whose transition to `paid` happened on that UTC day (read from `order_status_history`). `orders_still_paid` is how many of them are still paid now, so a later cancellation is visible without rewriting history.

## Design notes worth reading

- **Idempotent**: the key comes from the report day, not the run time, and the file is overwritten. Scheduler retries and manual re-runs never create duplicates. `{"date":"YYYY-MM-DD"}` regenerates a finished day.
- **Half-open UTC window** `[00:00, next 00:00)`: a payment at exactly midnight belongs to exactly one report.
- **Least privilege**: the DB user can only `SELECT`; the role can only write under `reports/`.
- **No password anywhere**: `rds-db:connect` plus a 15-minute token generated by `platform/pgdb.IAMAuth`; TLS verify-full with the embedded RDS CA bundle.
- The Lambda must live in the VPC; it needs a path to S3 (gateway endpoint or NAT).

## Configuration

Generated from the contract:

#### `lambda-nightly-report`

| Variable | Required | Secret | Example | Description |
|---|---|---|---|---|
| `DB_HOST` | yes | no | `<rds-endpoint>` | RDS endpoint host name of the orders database (must match the TLS certificate) |
| `DB_PORT` | no | no | `5432` | Default 5432 |
| `DB_NAME` | yes | no | `orders` | Orders database name |
| `DB_USER` | yes | no | `orders_report` | Read-only database user created WITH rds_iam |
| `REPORTS_BUCKET` | yes | no | `<reports-bucket>` | S3 bucket for reports/YYYY/MM/DD.csv |
| `AWS_REGION` | yes | no | `us-east-1` | Set by the Lambda runtime |
| `LOG_LEVEL` | no | no | `info` | debug/info/warn/error |

IAM actions:

| Action | Resource | Why |
|---|---|---|
| `rds-db:connect` | `arn:aws:rds-db:<region>:<account-id>:dbuser:<db-resource-id>/orders_report` | IAM database authentication as the read-only user |
| `s3:PutObject` | `arn:aws:s3:::<REPORTS_BUCKET>/reports/*` | Write (overwrite) the daily CSV |
| `ec2:CreateNetworkInterface / DescribeNetworkInterfaces / DeleteNetworkInterface` | `*` | VPC-attached Lambda (managed policy AWSLambdaVPCAccessExecutionRole) |
| `logs:CreateLogGroup / logs:CreateLogStream / logs:PutLogEvents` | `the function's log group` | Logs |

## How the coach will deploy this

`make lambda-zip` -> `dist/lambda-nightly-report.zip` (arm64, `bootstrap`). Terraform: function in the private subnets, security group to RDS, S3 gateway endpoint, reports bucket (versioning on, lifecycle), Scheduler schedule `cron(5 0 * * ? *)` with its invoke role, alarms on Errors and on a missing file. The `orders_report` DB user is created by the bootstrap SQL in HANDOFF section 4 (it needs `rds_iam`).
